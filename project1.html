Colorizing the Prokudin-Gorskii Collection

Reconstructing color photographs from Sergei Prokudin-Gorskii's early-1900s three-exposure glass plate negatives, by finding the pixel translation that brings each channel in line with the others.

Context: Each glass plate is a single tall scan stacking three exposures of the same scene, taken through blue, green, and red filters, from top to bottom. Mechanical movement between exposures means the three channels aren't pixel-aligned so recovering color means finding the 2D integer shift for each channel that lines it up with the others. I treated this as a discrete search problem where I try each candidate shift and score each one against a reference channel. Then, I keep only the shift with the best scores. To accommodate both small JPEGs and full-resolution scans (.tif), I used different scoring metrics and implemented a coarse-to-fine search strategy for the larger scans.

Single-scale alignment for JPEG images

For the three low-resolution example plates, I ran brute-force search over every integer displacement in a ±15 pixel window, scored with both NCC (normalized cross-correlation) and L2 (Euclidean distance). Both metrics agreed exactly on all three images:

Exhaustive search works here since there is only 31 by 31 (=961) candidate shifts to check per channel since the image is so small. This only take around 2 seconds each and is fast enough.

Multi-scale pyramid alignment (all 14 example images)

The full-resolution .tif scans are 10–20× larger on each side of the images than the JPEGs. Hence, displacements can exceed 100 pixels so using brute force is too slow. Instead, I built a recursive coarse-to-fine Gaussian pyramid where I repeatedly downsample, align at the smallest scale, then work my way back up. Lastly, I refined the estimate with a small local search at each level. The three JPEGs above also go through the same pyramid path and they mostly result in identical offsets to the single-scale search (with the outlier being R offset on monastery.jpg). This suggests that both methods agree and are valid.

Where the algorithm failed and why

Every image above aligned correctly under NCC at both single- and multi-scale. On the other hand, L2 metric did not do as well under the pyramid method as it disagreed with its own single-scale result on two images (cathedral and additional2).

  • cathedral.jpg: L2 single-scale found R = (12, 3), L2 pyramid found R = (10, 28), wrong.
  • additional2.jpg: L2 single-scale found R = (12, 3), L2 pyramid found R = (44, 5), wrong.

This could be due to L2 penalizing intensity differences between channels. For example, if channel G is brighter than channel B for reasons no related to alignment, L2 will be biased towards whatever offset minimizes brightness difference instead of structural differences. This results in the algorithm locking onto a shift that matches average brightness rather than scene structure for heavily downsampled, low-detail pyramid levels. The moment the estimate on the coarse level is wrong, the narrow local refinement search at each finer level is not wide enough to recover. NCC does not face this problem because it is the cosine similarity of mean-centered signals so it removes the means and scale by norms before comparing. Hence, NCC is invariant to the brightness difference between channels that L2 is affected by. Hence, I decided to keep NCC as the default metric throughout this project and L2 is used only at the required comparison points.

Bells & whistles

Exact wraparound removal

I implemented a circular shift with np.roll so that every aligned channel wraps a band of pixels in from the opposite edge. Rather than guessing where the band of rubbish pixels is, I computed it from the known offsets. For an offset (dy, dx), the invalid region will be max(0, dy) rows at the top or max(0, -dy) rows at the bottom. As for the columns, it will follow the same logic. Then, I take the tightest bound across all three channels to get the exact shared 'valid' region without the thresholds.

Automatic border cropping

After the exact wraparound crop, a heuristic pass scans inward from each edge, comparing each row or column's brightness to the image's overall median, to catch any leftover physical plate border the exact method wasn't targeting.

Automatic contrast per channel

The raw aligned images had visibly different black points and white points per channel that are not due to misalignment. Stretching each channel independently between its own 1st and 99th percentile corrects both an additive offset and a multiplicative gain difference between channels.

Automatic white balance (tried but did not end up using)

I also implemented gray-world white balance, which scales each channel such that its median matches a shared target. However, during testing, it consistently made the results worse. Potentially because gray-world assumes the average pixel in a scene should be neutral gray but that assumption does not hold for scenes that are dominated by one color. For example, sky, trees, etc. I kept the function in the code, but the final pipeline uses per-channel contrast alone.

Edge-based alignment features

For some full-resolution .tif scans, alignment was on Sobel gradient magnitude instead of raw pixel intensity. This targets one of the failure case in this dataset where a channel whose brightness response to the same scene content differs sharply from the others. In this specific example of Emir, the brightly colored robe might be bright in one filter and dark in another. Edges correspond to physical scene structure, which survives that kind of filter-response mismatch far better than raw intensity does.
